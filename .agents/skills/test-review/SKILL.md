# XiHan.FlowDesigner 测试审查

## 判断标准

每个用例给出「保留、改写、合并或删除」的结论，并说明它保护的可观察契约。

- 保留：缺陷复发时会失败，覆盖流程定义的读入与校验、编辑操作与逆操作、公开方法与事件、元素的部件与键盘、扩展登记、语言包或与引擎的一致性。
- 改写：只复述实现、mock 后证明 mock、断言私有字段、依赖脆弱的 DOM 顺序或用固定延时碰运气。
- 合并：与相邻用例输入和断言等价，没有提供新的失败定位。
- 删除：不可能失败、只验证常量或快照自身，或已被更清楚的用例覆盖。

## 本仓专项

- core 的用例跑在 Node 里，不碰 DOM；编辑操作要核「执行再执行逆操作回到原状态」，读入要核非法输入给出的问题码与路径。
- runtime、designer 的用例在文件头写 `// @vitest-environment jsdom`。jsdom 证明不了真实布局、计算样式与动画，这类结论要到文档站或 playground 的真实浏览器里核，不要在 jsdom 里断言像素。
- 比较 DOM 元素的顺序时比文字或 id：`toEqual` 对 DOM 元素按结构比，同样的空元素换了顺序也算相等。
- 设计器包的单条超时上限写在 `flow/packages/designer/vitest.config.ts`（约为本机最慢一条的十倍）；用例变慢先查原因，不靠继续加大上限。
- 假定时钟只在控制时间的用例里启用，并在 `afterEach` 还原；用到 localStorage 的用例结束时清掉。
- XiHan 工作流引擎预设的一致性用例读同级 XiHan.Framework 的源码，找不到时整组跳过；审查时确认本机这组真的跑了，不把「跳过」当成「通过」。

输出按风险排序，附文件与行号。除非用户要求运行，否则以静态审查为主；不因缺少新测试自动修改代码。
